# 硬件控制与接线

DeckLab 可以通过控制器给指定板卡发送复位或进入下载模式的请求。串口用于观察板上的输出，刷机 USB 用于枚举和实际读写。三个连接应在同一板卡上核对后再登记。一个控制器可以有多个槽位，一个 DeckLab 控制机可以连接多个控制器和多条数据线。

## 绑定 Home Assistant 工位

1. 接好板卡的串口、刷机 USB 和控制线。进入「工位接线」，填写 Home Assistant 地址和可访问该工位实体的凭据。
2. 选择控制器，按控制器上的原编号确定槽位。若槽位已经绑定且板在线，先核对当前占用。更换开发板时，使用所属设备的「换板」入口解除原关联。
3. 在空槽位或待确认槽位用「进入下载模式并识别」。控制机发送这一个槽位的请求，随后核对新出现的 USB 连接和板卡身份。身份不明确时，按接线人工选目标，保存关联前复核序列号。
4. 设置后，从板卡页的「电源与启动」使用复位或进入下载模式。含远程电源动作的授权应限定到同一板卡和可操作槽位。

访问凭据保存在控制机。实体状态可用于显示控制器能力，是否已重启仍要以板上串口和 USB 枚举为准。若控制器已接管下载模式条件，直接使用已绑定的「进入下载模式」动作。设备更换后的重新绑定见 [设备身份](device-identity.md)。

## 使用外部控制器

管理员可用硬件配置在指定板卡或工位启用固定动作。进程入口使用固定的程序和参数，执行器把板卡身份、动作及请求编号作为参数或结构化数据接收。配置示例包括 [本机控制](../../examples/hardware.json)、[BMC 控制](../../examples/hardware-bmc.json)及 [Home Assistant 适配器](../../examples/home_assistant_control.py)。

控制机检查执行者权限、目标板身份和维护占用，再调用适配器。适配器可返回控制信号已接受、执行失败或结果未知。控制机用新的串口或 USB 状态独立判断实际效果。

## 本机刷机流程

手动进入下载模式后连接 USB 数据线，打开刷机工作区即可自动检测。若当前板已绑定槽位，可确认由 DeckLab 进入下载模式并继续原操作。多块下载设备同时存在时，页面保留原目标，并要求为无法唯一确定的设备选择正确连接。

普通安装包内置刷机执行器和临时加载器。自定义硬件可显式配置 `DECKLAB_HARDWARE`、`DECKLAB_FLASH` 或相应的加载材料。设备不支持的操作会在当前页面说明。[刷机工作区](flashing.md) · [环境变量参考](../reference/environment.md)

## 平台接入与执行合同

集成方先确认上层任务已占用正确设备，再以板卡序列号、当前连接和稳定请求编号提交动作。回执没有到达时，先用原编号查询任务。执行过程可以通过[后台任务](tasks.md)以及[串口记录](serial-and-ssh.md)检查。用于平台的 API、幂等提交和恢复参见[平台集成](platform-integration.md)。

## USB 找不到下载设备

先确认使用的是数据线、板卡已进入下载模式，并打开控制机的刷机工作区检查「连接详情」。Windows 上核对设备管理器和驱动。若 BootROM 能连接、发出 U-Boot 启动命令后接口消失，记录板型、USB 连接位置、链路速率和任务诊断编号。需要使用 USB 2.0 兼容台阶时按当前板卡与端口配置，见 [刷机诊断](flashing.md)。
