# 刷机工作区

一次刷机需要确定三件事：设备是哪块板、本次用哪个包、写入哪些介质。设备页的入口优先显示当前板。首页的刷机入口先选择镜像，也可以为没有串口的设备选一个物理 USB 连接。

## 按操作选择入口

| 入口 | 镜像来源 | 执行范围 |
| --- | --- | --- |
| 普通刷机 | 镜像商店、已下载镜像、上传文件、控制机路径和下载 URL | 整包或指定分区，可选配套固件，并核对实际写入范围 |
| URL 极速刷机 | HTTPS/HTTP 系统包 URL，镜像商店可直接填入 | 从链接边下载边解压并写入目标系统盘，覆盖 GPT |
| 内存启动 | 支持的原始镜像包 | 把临时引导与系统送入 RAM，见 [内存启动](ram-boot.md) |

接好刷机 USB 或确认由 DeckLab 让板进入下载模式。工作区在准备阶段自动跟随枚举变化。若当前设备已经选定，接入另一块板时保留原选择。

## 普通刷机

1. 选镜像，看「镜像布局」确认包内系统分区和固件。配套固件可从镜像库、单独固件包或主包中的 NOR 分区定义选择。固件包也可以单独刷写。
2. 确认目标介质。K3 可能同时报告 NVMe、UFS、eMMC 或其他介质。多块盘时明确选择目标系统盘。若要看具体的旧分区和固件版本，在设备区域读取存储。
3. 选「整包刷写」或「指定分区」。整包会根据包内布局重建目标系统盘的 GPT。指定分区使用当前已核对的布局处理选中的载荷。NOR 的临时 MTD 映射定义分区的起点与长度，擦除范围由预览逐项列出。
4. 点「预览写入范围」。依次核对 NOR、EC 和各存储介质的预计操作。有支持的 EC 载荷时，查看本次更新选择。底栏可调整回读校验和刷后复位。按确认后开始写入。

板上已有内容和包内布局来自不同来源：读取设备显示板的现状，镜像布局显示包内容，核对页显示本次变化。留意标为保留的介质，以及需要重建分区表的目标盘。

## 观察进度与结果

「执行与结果」提供当前分区、累积字节、刷写速率和命令摘要。展开详情可看对应回执。写入已完成与回读校验通过是两个结果。跳过剩余校验时任务保留已做的操作和跳过回执。

确认过期时可用底栏「重新检测设备」生成新的预览。若已接受启动临时 U-Boot 的命令，但控制机等不到下一阶段的 USB 接口，先从串口查看实际启动阶段。可控板卡可以从工作区确认重新进入下载模式。写入结果未知时，先回查原任务和设备状态，再决定后续动作。

## 加载器、备份和性能

K1 与 K3 的下载流程、识别能力及可用存储范围有差异。临时加载器按芯片、设备能力和包内容选择。配置 `DECKLAB_FLASH_USB2_PORTS` 可在匹配的端口启用兼容路径。`DECKLAB_FLASH_EXECUTOR` 和 `DECKLAB_FLASH_LOADERS` 用于部署自定义执行器或加载材料。

可在支持的 NOR 写入路径选择备份用于下载。按载荷长度计算的摘要只说明已核对范围的字节，任务回执中同时保留分区和介质范围。[后台任务](tasks.md) · [刷机性能](../reference/flash-performance.md)

自动化通过原 [HTTP API](../reference/http-api.md) 或 [MCP](mcp.md) 使用相同的目标盘、预览、确认和结果接口。
