# ADB USB 调试

ADB（Android Debug Bridge）用于通过 USB 在板上打开 shell、传文件以及触发后台任务。板上需要启用 `adbd`，控制机需要能枚举该 USB 调试接口。设备页的「ADB」标签属于当前板卡，可与串口、SSH 分开查看。

## 识别板卡

控制机按当前 USB 连接读取板卡序列号和 Linux 启动编号。两份由同一系统镜像克隆的板可能有相同的 ADB 序列号。换口后，新开会话、查询接线或启动用例时可跟随唯一匹配的板卡使用新路径。硬件配置中的路径仍是首选位置，启动后的操作继续使用该次确认的路径。页面提示身份不唯一时，先查接线或等待重新枚举，再在对应板卡页打开会话。

ADB 需要板端接受连接，是否要求主机密钥授权取决于板端镜像。串口可以用来检查系统是否启动，也能查看 `adbd` 的服务状态。

## 自动诊断

从设备页打开 ADB 时，如果控制机找不到这块板的在线调试连接，DeckLab 会尝试通过同一块板的串口读取 `adbd` 状态、当前启动的近期 USB 事件，以及板端 USB 设备控制器状态。连接提示和本次任务详情会显示读到的证据。例如，`adbd` 在运行，近期 USB 日志显示连接关闭，此时可以按提示处理板端服务。

取证使用已经登录并停在空闲 Linux Shell 的串口。串口被占用、未登录或没有可确认的提示符时，页面会说明证据不可用。取证命令只读状态，重启 `adbd` 由操作者决定。

## 后台任务和断开

触发用例时，ADB 只是一种执行和采证通道。板进入深度挂起后，ADB 可能暂时消失，串口仍可提供唤醒和命令结果。任务保留原操作和已收到的回执，连接回来后再对照本轮记录。若只看到命令已发送，应继续查看任务状态和[原始串口归档](../operations/log-operations.md)，确认板端是否执行完成。
