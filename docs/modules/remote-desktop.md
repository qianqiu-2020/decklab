# 图形会话与输入

DeckLab 面向连接专用控制设备的工位控制机。目标板不必安装 DeckLab，也不必运行
GNOME 或 SSH；图形能力来自管理员明确配置的远程桌面或控制设备。无图形接入时只返回不支持，
串口、复位和刷机仍独立工作。已有平台控制服务可以通过独立适配保留。

## 网页连接与自动检测

打开已识别板卡的「桌面」时，控制机主操作者可通过已核对身份的 USB ADB 自动连接 Debian GNOME。控制机核对板卡序列号和本次启动编号，读取 AccountsService 的用户状态与当前活动图形会话。首次设置向导运行时，连接镜像提供的引导桌面，用画面中的向导创建普通用户。若板上接着显示器，远程扩展屏可能只显示壁纸。点「将向导移到远程屏」会发送 GNOME 的 Super+Shift+右箭头，将当前窗口移到右侧屏幕。之后再次打开桌面，进入系统登录界面。若尚无用户且向导未运行，页面会说明如何继续。控制机通过 USB 取得当前入口证书和凭据，只用于本次连接。

已保存的 Debian `rdp` 入口使用板卡当前 IP 的 3389 或 3390 时，打开「桌面」仍会读取当前登录阶段。USB ADB 不可用时，页面会说明无法自动判断首次设置状态，并可继续尝试已保存的远程桌面连接。

设备页「历史日志」的「关键操作」记录这次打开使用的连接入口、协议和建连结果。「远程桌面 · ADB」显示已核对的 USB 路径和读取到的登录阶段。连接失败时，在桌面页展开「连接错误详情」可查看对应的协议错误。

手动设置支持其他镜像、VNC 和自定义地址。未识别设备需先完成识别；没有图形接入配置时，
打开该页会展示连接表单，并自动检测该设备最近识别出的 IP 上的 RDP 3389／3390 和 VNC 5900–5902。
只选取最多四个非回环、非链路本地、非 Docker／veth 接口地址；不扫描整个网段，不猜测密码，不执行登录或键鼠动作。
检测依据 RFB 横幅和 RDP 安全协商，单纯 TCP 端口可连接不代表存在对应服务。没有结果时仍可手工填写。
手工填写地址后，RDP 的 3389／3390 会一并重新检测，便于同时找到系统登录和桌面共享；自定义 RDP 端口及 VNC 只检查所填端口。Agent 检测仍限于已识别 IP 和固定端口。

检测到多个服务时选择其一，填写用户名／密码后“保存并连接”。网页新建的 RDP 连接使用 FreeRDP，默认接受同一主机与端口的当前证书，重刷后可继续连接。可信网络以外可在“证书校验”选择系统信任链或固定 SHA-256。已有固定指纹的连接若遇到证书更换，可选择“关闭证书校验并重连”，沿用已保存的账号密码。连接继续使用 TLS 或 NLA。
GNOME 和 LXQt 都以目标实际开启的 VNC 或 RDP 服务为准。

连接表单沿用 `WebSettings` 的 `desktop` 文档持久保存，密码仅存控制机私有配置；网页仅返回用户名、是否已保存密码等连接元数据。
只有网页操作者可以修改；Agent 的设备授权允许只读检测，不授予配置或未开放桌面的使用权限。

Debian GNOME 镜像的系统远程登录通常使用 3389，入口用户名默认为 `rdp`；在开发板串口执行 `sudo grdctl --system status --show-credentials` 查看当前入口账号和密码。连接进入 GDM 后，再使用 Linux 用户登录。当前用户桌面共享使用“设置 → 系统 → 远程桌面 → 桌面共享”中显示的独立账号、密码和端口；3389 被系统远程登录占用时通常为 3390，以设置页为准。选择 RDP 后，连接设置与串口同时显示。点「填入串口」后按回车，按串口输出填写凭据，再点「保存并连接」。

保存只应用该设备的图形项，不重启采集器，也不激活其他尚未应用的系统配置；原台账约束、显示器描述与其他板卡配置保留。
已有图形连接时必须先明确断开，不能通过改配置接管别人。原密码只允许对相同协议、地址、端口、用户名复用；
地址或设备连接代次变化后，旧检测结果失效。密码和访问 URL 不返回浏览器／模型，不写入任务历史。

连接失败时，网页“连接错误详情”可展开与复制；HTTP 的 `details` 和 MCP 错误保留相同信息：协议、引擎、无凭据的主机端口、失败阶段、异常类型／原因及堆栈，FreeRDP 另带原生错误码、名称与说明。证书拒绝不推断为密码错误；认证失败也保留原生账号禁用、密码错误等具体说明。服务端未报告认证拒绝时，不根据黑屏或登录画面猜测密码是否正确。

原生 stderr 仅在建连期间有界缓存，失败后脱敏返回；成功即清空，后续内容只排空不留存。密码、含凭据的 URL、令牌和 Authorization 隐藏；异常堆栈不包含局部变量。堆栈与原生输出达到上限时通过 `*_truncated` 标明，诊断不成为重试输入、自动接受证书或扩大配置权限的依据。

## 接入

网页配置中的 `desktop` 文档与 `DECKLAB_DESKTOP` 指定的服务端 JSON 使用同一格式，按板卡
正式序列号绑定，不按 IP、COM 口或模型传入的地址猜设备。`secret_url` 会在配置导出时隐藏；
认证在服务端执行，密码不进入 MCP、任务或网页响应。

```json
{"boards":{"设备正式序列号":{
  "provider":"vnc",
  "secret_url":"vnc+plain://:服务端保存的密码@已配置主机:5900",
  "display":"display-0",
  "display_kind":"physical",
  "scale":1,
  "allow_agent":true
}}}
```

`provider=vnc` 复用 vncdotool；`provider=rdp` 复用 aardwolf，使用该库的
`rdp+ntlm-password://域\\用户名:密码@主机:3389` 地址，`width`、`height` 设置请求尺寸。
RDP 原有配置默认使用 aardwolf。需要 Graphics Pipeline 和系统远程登录重定向的 GNOME
入口使用 `"engine":"freerdp"`，复用 FreeRDP 的原生协商、解码与 RDSTLS，不修改目标服务：

```json
{"boards":{"设备正式序列号":{
  "provider":"rdp", "engine":"freerdp",
  "secret_url":"rdp+ntlm-password://用户名:密码@已配置主机:3389",
  "certificate_sha256":"已通过可信渠道核实的证书DER编码SHA256，64位十六进制",
  "display":"system-rdp", "display_kind":"virtual", "allow_agent":true
}}}
```

`certificate_sha256` 固定初始连接的证书，证书不匹配即拒绝；不设置时校验系统信任链和主机名。
系统登录后续重定向的目标证书由 FreeRDP 根据已认证连接中的交接信息校验，不因重定向标志自动放行。
该引擎禁用不经过 TLS 证书校验的 Standard RDP 回退；目标须支持 TLS、NLA 或 RDSTLS，连接失败不会自动降级到旧安全层。
此引擎及其私有库随完整控制机安装包提供，不要求 AI 客户端或目标板安装组件。
旧配置保持原引擎，不会因升级静默改变自签名证书的既有接入方式。

RDP 默认 `text_input=unicode`，通过原生 Unicode 按键输入。部分 xrdp 服务或 GNOME 当前键盘映射不接收中文按键，
可在该设备配置 `"text_input":"clipboard"`，复用原生文本剪贴板和 Ctrl+V；需要目标应用支持粘贴。
此模式会替换目标会话的剪贴板，不同步控制机系统剪贴板、不提供文件传输。
原生客户端可能暂存目标文本剪贴板通知于进程内，关闭连接即丢弃；不会写入日志或 MCP 响应。
网页连续桌面可由用户明确读取远端文本剪贴板，详见下文。
服务端拒绝或超时后不自动改用另一种方式重发，应重新截图核对实际结果。
连接由私有运行进程持有，不启动主机可见的远程桌面窗口，不向模型提供凭据或主机 shell。
VNC 的传统认证与 aardwolf 接入不能作为服务器证书已核验的证明，应绑定管理员认可的
控制网络或已有可信隧道；当前适配不声称提供公网可信身份认证。

当前完整包的图形客户端覆盖 Linux/Ubuntu x86_64 与 Windows x64。源码运行时在控制机的私有 Python 3.12 环境安装 `requirements-mcp.txt` 和
`requirements-desktop.txt`，`DECKLAB_MCP_PYTHON` 选择该解释器。客户端不安装这些依赖。
完整包复用内置 MCP 私有运行时携带这些依赖；仅更新网页不会增加原生图形组件。Linux 构建保持 Ubuntu 22.04 / glibc 2.35 基线，构建容器使用 deadsnakes Python 3.12；不会给安装主机添加该软件源。依赖版本、官方 wheel 摘要及原生许可证随包保留。

测试适配可用 `provider=helper`、固定绝对路径 `argv` 复用已有受限图形助手：
助手从标准输入接收单个 JSON，返回 `ok`；`status` 返回显示代次，`screenshot` 返回 PNG，
其余动作只有 `click`、`key`、`text`、`scroll`。不接受模型提供的命令或文件路径。
现有 GNOME 原型可接入此适配，但它不是其他目标板的必要条件，不能替换其原占用或访问身份。

## 会话、观察和输入

网页与 MCP 调用同一组 `/api/desktop/{sessions,open,frame,input,close}` 接口管理原生连接，
网页连续画面与实时键鼠另走该会话的 `/api/desktop/stream`，不新建目标连接。
当前连接范围的 Agent 令牌不能调用，单设备令牌按控制面注入的正式序列号校验。
每块板只持有一个受管图形连接；其他操作者不能静默建立竞争连接。刷新网页遗留的连接可由人工明确选择“断开原连接并连接”恢复，Agent 不能执行人工接管。串口插拔或重枚举后必须重新观察，并在当前连接上重建原输入占用。关闭受管连接不注销
目标桌面、不结束其他访问入口，也不释放业务台账的占用。

截图带会话 ID、设备序列号、显示器、物理／虚拟类型、图像像素宽高、配置缩放与采集时间。
输入坐标始终是截图像素坐标。截图还返回 `frame.id`，输入必须引用本调用者最近观察到的画面。
成功获取新截图后，同一调用者的旧 `frame.id` 不再接受新输入，排队中的输入也在实际执行前核对。
分辨率或显示代次变化后旧观察失效；不把 D-Bus 或网络发送成功当成应用已经响应。

离散输入使用既有 `SerialTransactions` 检查板卡维护锁和输入所有权，并创建既有后台任务。
`request_id` 按原请求去重；任务只记录动作、执行结果和输入摘要，不持久化输入文本或图片。
同一 `request_id` 与原输入仍返回原任务，不受截图更新影响；修改输入后复用该 ID 会拒绝。
结果未知时保留原任务并清除旧观察，必须重新观察，不换请求 ID 重放。撤销 Agent 授权会取消其任务、关闭
图形连接并释放该连接的输入占用；已经送达目标的输入不能撤销。

MCP 的 `capture_desktop` 直接返回图片内容块和元数据；`desktop_input` 可附带操作后的图片，
不向对话返回 Base64 字符串或只有控制机本地路径。客户端应从实际画面判断操作效果。

## 原平台占用

控制台保存固定用途、申请、释放和占用历史。DeckLab 不建立另一份业务设备池，也不接受
客户端自报的 lease 字符串。纳管板在配置中绑定 `reservation`：

```json
{"origin":"https://原控制台地址","credential_file":"/私有目录/console.json",
 "device_id":"原台账设备ID","task":"原任务标识","requester":"原申请主体",
 "lease_id":"原占用标识"}
```

凭据文件包含 `origin`、`username`、`password`，`username` 必须是原申请主体。
每次连接、截图和输入前查询原 `/api/ops/v1/devices`，核对同一设备、占用、任务、主体、
`reserved` 状态及 `desktop` 操作范围；接口不可达或不匹配即拒绝。占用超期沿原控制台规则
处理，不擅自释放或转交。输入前要求原占用为空闲，并向原接口登记 running；完成登记 idle，未知结果登记 unknown，状态回执丢失不重发。该原接口仅允许设备管理主体确认运行结束，配置的执行凭据须具备原设备管理范围；DeckLab 不修改其权限。没有配置时明确标为本地使用，不能宣称跨平台独占。

这项读取校验不代表刷机、复位等所有原入口已经共享同一台账锁。其他入口的统一准入和“检查空闲→登记运行”的原子条件更新仍须在原系统接通，不能把检查当前占用当成完成跨平台原子互斥。

## 人用连续桌面

网页“桌面”与串口、SSH 会话相邻，显示在同一工作区；切回终端不会建立第二个串口采集器。
同一页面内返回终端保留桌面连接并释放按住的键鼠，隐藏时不授权新的桌面输入；再次打开后
先确认已绘制画面，再恢复控制。切板、断开或离开该页面仍结束对应连续通道。
支持连续画面、鼠标按住与拖动、按键按下／抬起及组合键、滚轮、文本输入、双向文本剪贴板、
缩放和全屏。完整包本地托管浏览器资源，客户端无需安装远程桌面组件。

服务端原生 vncdotool／aardwolf 或 FreeRDP 接收目标的 framebuffer／视频更新，按事件推送 PNG 更新区域，
点击远程画面后使用键盘。全屏时，支持 Keyboard Lock 的浏览器会请求捕获 Win / Super 和 Tab；离开画面会释放。若系统保留实体 Win 键，可点工具栏「Win / Super」发送给远端。

浏览器复用未修改的 noVNC 1.7.0 Display 和 Keyboard 组件绘制、处理键盘。
不通过定时截图模拟连续桌面，不重写 RFB／RDP 协议；截图 MCP 与网页使用同一个受管原生连接。
浏览器只连接 DeckLab 同源的 `decklab-desktop-v1` WebSocket，不接触目标密码或任意目标 TCP 通道。
控制面沿既有本地 Unix socket 或经过节点凭据和证书校验的 HTTPS 后端链路转发。
WebSocket 封装复用离线固定的 wsproto／h11，来源、摘要及许可见 [第三方清单](../../THIRD_PARTY.md)。

实时输入沿用原设备授权、板级占用证明、维护守卫和 `SerialTransactions`。证明仅在消息中提交，
不放入 URL。每个通道只允许一个待确认输入，物理键鼠不自动重放。画面实际绘制后才确认观察；
模式或串口连接代次变化要求重新观察，旧画面的输入拒绝执行。输入确认只表示原生传输已接受，
应用效果仍须看画面。失焦、切换设备、断线或撤销时释放按住的键鼠；
清理未确认则关闭原生连接，不能把未知结果当成成功。未知输入不自动重连重发。
实时事件不逐个创建后台任务；仅保存会话结束与清理摘要，不保存按键、文本或图片。

聚焦远程画面后用 Ctrl+C、Ctrl+V 复制粘贴。粘贴时先发送本机文本，再在目标应用执行粘贴；
复制时在目标应用执行复制，再把远端文本带回本机。终端可用 Ctrl+Shift+C、Ctrl+Shift+V。
RDP 文本剪贴板支持 Unicode。传统 VNC 的剪贴板使用 Latin-1，含中文的短文本通过键盘输入。
浏览器限制写入本机剪贴板时，可从“剪贴板”面板手动复制远端文本。
不提供音频、文件剪贴板或文件拖放；文件传输使用现有设备文件接口。

### 现成协议与组件边界

浏览器只负责显示和输入事件；VNC／RDP 的认证、解码、服务端重定向及目标剪贴板
交给原生客户端。noVNC 提供显示、键盘与输入映射组件，不另造传输协议。
协议凭据不交给浏览器，也不借用控制机的系统剪贴板。

接入其他工作台时复用公开的设备、任务和会话 API；已有业务台账与租约继续由原平台持有。
Web 和 MCP 不另建一份设备池、凭据记录或输入占用状态。目标不支持图形能力时，
串口和硬件控制仍可独立使用。

## 验证边界

隔离回归使用生成的 PNG 和模拟服务，检查图片内容、设备与令牌隔离、显示模式变化、
输入所有权、去重、未知结果和撤销。原生客户端另需在隔离桌面实际检查画面及输入效果。
真实设备验证须核对原占用与接线，不影响其他任务或既有业务入口。虚拟显示器、云 BMC 与真实工位控制硬件的验收分别报告。

原 aardwolf 引擎固定为 0.2.17，复用其视频队列、MCS 位图解析和解码；适配层合成截图并裁去编码行填充，不另写协议。关闭只结束本连接的传输，不请求目标桌面退出。默认 Unicode 按键路径可发送基本多文种平面字符（含常用中文），实际输入仍取决于目标键盘映射和应用；`text_input=clipboard` 走原生 Unicode 文本剪贴板，不受此按键路径限制。aardwolf 接入的 xrdp 不发送登录确认时，可由管理员在固定连接地址配置 `?autologon_confirm=0`；不会自动关闭认证确认。FreeRDP 地址不接受该参数，沿用原生连接协商。


MCP 的 `capture_desktop` 返回原始画面尺寸和 `frame_id`。拖动窗口或滑块时，向
`desktop_input` 传入 `action="drag"`、起点 `x/y`、终点 `end_x/end_y`。
坐标使用截图像素。每次新的操作先取得新截图，响应丢失时沿用原请求编号。
GNOME 可用 `action="key"`、`keys=["Super_L","a"]` 打开应用列表。
LXQt 可根据截图点击面板上的应用菜单。
