# NOR 刷机工作区

本次改版目标是：先读出并备份整片 NOR，查看现有分区内容，再选择替换文件，
核对写入范围，完成刷写和回读校验。保持同一硬件任务、同一物理 USB 位置，
不新增串口读者，不把“加载临时环境”当成存储写入。

## 交互设计审计

沿用 DeckLab 已有导航、原生表单、系统字体和随操作系统切换的明暗主题。
亮色强调色为 `#245F94`，暗色为 `#7CC5FF`，继续使用现有 CSS 变量。
本次是保留现有风格的工具界面改版：设计变化 3/10，动效 1/10，信息密度 5/10。

现有刷机面板把设备检测、镜像导入、分区选择、预览和执行结果纵向堆放。
一个进度条混用镜像下载、加载器准备和刷写进度；未显示整片备份和分区版本。
保留既有设备选择、镜像 URL、上传及后台任务恢复行为，重新组织为以下四步：

1. **连接与备份**：选择下载模式设备，加载预装的 RAM 刷机器，读取全部 NOR，
   提供可下载备份及 SHA-256。无需先上传一个无关镜像才能读取。
2. **选择替换内容**：一行一个分区，显示名称、偏移、容量、现有版本、构建时间、
   内容摘要及替换文件。默认不勾选分区；env 与 bootinfo 明确为配置内容。
3. **核对写入范围**：显示所选分区、文件字节数、补零范围、擦除风险上限。
   修改文件或选区后原预览立即失效。完整 NOR 恢复作为独立的高级路径。
4. **刷写与校验**：显示当前阶段及实际字节进度；分别展示写入、回读校验和启动结果。
   写后回读文件可下载。校验失败不能展示为刷机成功，不自动重刷。

## 页面操作

1. 让指定板卡进入下载模式，按 USB 位置选择设备，点击“读取并备份 NOR”。
   不需要先上传镜像；预装 FSBL 和 U-Boot 只进入内存。
2. 读取完成后可下载整片备份。查看六个分区的版本、构建时间和 SHA-256。
   env、bootinfo 显示为配置；没有版本标记的固件明确显示未知。
3. 在“镜像来源”导入完整固件包后，勾选分区会使用包内映射到该分区的内容；预览时缺少映射会报错。单文件替换可直接在分区行选择缓存文件，或从商店“下载并使用”，完成后自动绑定该行，不必再次选择。顶层导入一个文件时，只有恰好一个已选分区才自动绑定；不会自动把它用于多个分区。可混用一个固件包与多个独立文件。
4. 点击“预览分区写入范围”，核对偏移、容量、字节数、摘要及擦除风险，
   再点击“确认分区并刷写”。同一个后台任务重新检查板上内容后才写入，随后整片回读。
   分别查看写入和校验结果，下载写后回读文件；不自动复位或重刷。

只需要备份时，点击“结束准备并保留备份”，文件仍按现有保存期限保留。
关闭面板或刷新浏览器不会重启任务。执行记录保留原请求编号，可查询响应丢失的原任务。
等待选区最多十分钟；超时或取消不会撤销此前已完成的写入。

页面沿用原生表单与 progress，支持键盘确认、明暗主题与手机纵向分区对照。
镜像下载、RAM 准备、整片读取、刷写和回读分别显示阶段及实际进度，等待选区时不伪造百分比。

## 已实现的后端基础

执行器源码提交：`7c96d857b36b7d8c67f5f5edf41a593649cef3ca`。
Linux／Windows amd64 编译通过；Windows 未做原生硬件验收。
Ubuntu BMC 的单板临时后端与本机 Web 已完成下述实测；正常服务未替换。

执行器新增两个操作：

- `nor-read-profile`：使用后端已固定的 RAM 材料生成只读准备配置，不需要业务镜像，
  不打开 USB、不写存储。
- `snapshot-nor`：在已检查的 `decklab-nor-v1` RAM 环境读取完整 NOR。
  只发送固定的根 MTD 读取与 upload 命令，不接受客户端分区名或 OEM 命令。

读取同时检查芯片、介质、唯一物理连接、8..256 MiB 容量和六个标准分区的现场偏移及容量。
按已证明的 RAM 缓冲大小分块读取，每块都要求准确长度与最终 OKAY；不把短读当成完整备份。
输出文件名固定到 task_id 与 attempt_id，私有权限，拒绝覆盖原操作文件。
阶段事件使用 `reading-nor`、`checking-nor-baseline`、`writing`、`verifying-nor`，
读取和写入进度均来自真实传输字节数，不生成假百分比。

安全 RAM NOR 的分区写入必须先读取整片基线。
协调器先将完整备份发布到现有 TransferArtifacts（传输文件）服务，再进入选区等待或执行。
若已有展示给操作人的基线，执行器在首次写入前重新读取并比较整片 SHA-256；
板上内容或备份文件变化时直接退出，不写任何分区。

写后回读覆盖整个 NOR：核对每个所选文件的实际扇区写入范围（包括补零），
并比较所有所选分区容量以外的字节，包括未选 env、其他分区及未分配尾部。
所选分区内文件尾部之后可能涉及硬件擦除块对齐，不假定整段都是 0xff；
这些字节也保存在整片回读文件中，但不编造其预期内容。
`readback_bytes` 是实际回读总数，`verified_bytes` 只计入实际比较的字节，二者不混用。
上述能力仅用于安全 RAM NOR 选区路径，不扩展旧的完整恢复或其他存储协议。

备份沿用现有文件配额、保存期限和下载鉴权，原始 env 内容仅保存在私有备份文件中，
不进入设备公开信息、版本列表或普通任务事件。Agent 不能通过其他人的 artifact id 下载。
取消选区、写入失败或校验失败时，已完成的备份继续保留；写入和校验结果分别保存。
校验失败但整片回读已完成时，仍可保存并下载该回读文件。

## 版本信息的依据

`seriald_core/nor_contents.py` 从分区实际字节解析 FIT 明确版本字段或组件版本横幅。
只报告能够定位来源的标记；FIT 描述与时间戳分别作为描述和构建时间。
文件名、镜像大小、分区名称不推导固件版本。多个不同标记全部保留，未知版本明确显示未知。
env 不解析或展示键值，bootinfo 配置不冒充软件版本。

旧的 sub23-1 整片备份离线解析可见 FSBL 的 U-Boot 标记；ESOS、OpenSBI、EDK2 的
FIT 没有明确版本字段，可提供真实构建时间和 SHA-256，版本保持未知。
本轮新读取的备份也得到相同类型的信息：FSBL 有版本横幅，其他三个 FIT 提供真实描述、
构建时间与 SHA-256，缺少明确版本字段时仍显示未知。
