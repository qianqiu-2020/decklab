# 设备存储与刷机工作区

从设备列表打开「刷机工作区」即可选择、上传和准备镜像。板卡进入下载模式后点击「检测设备」，沿用已选镜像和配套固件。分区图按实际容量绘制，竖线标出边界。宽度足够的分区直接显示名称，小分区可在下方图例查看全名和范围，指向或聚焦图例可高亮其位置。

页面提供“整包刷写”和“指定分区”。选择文件即上传，粘贴 URL 即下载；镜像商店或“已下载”中的“使用”直接带回当前工作区。准备文件不会开始刷写。失败后才显示重试，响应丢失时查询原请求，不重复提交硬件操作。

整包默认流程是选择镜像 → 预览 → 确认刷写，无需先点击“读取设备存储”。“目标开发板”下的“板上已有内容与备份”是可选入口；未进入该工作区时，整包复用原有完整包执行路径，不额外读取整片 NOR 备份或枚举系统版本。预览与执行仍自动核对设备身份、容量及范围；需要 RAM 加载器时先准备环境，NOR 恢复的擦除范围保持单独确认。指定分区查看与保留板上内容时，沿用原读取、备份与范围约束。

网页按准备、核对写入范围、执行与结果切换视图。计算预览时在准备页显示进度，收到计划后切到核对页。每种介质用同一比例分行显示分区、擦除上限和写入范围。表格并列显示分区容量和写入量，具体地址可展开查看。长分区表和执行日志在当前阶段内滚动，主要操作固定在底部。返回修改会作废本次预览，重新核对后才能开始。

等待确认期间显示剩余时间。确认超时且尚未写入时，页面明确说明镜像和备份保留，提供“重新检测设备”；该动作只重新检测，不重发旧确认、不自动创建读取或刷写任务。执行器尚有恢复占用时禁用此快捷入口，继续沿原人工核对机制处理。

回读校验可选“能力支持时校验”“必须回读校验”“不回读校验”。跳过回读不会跳过写前 SHA-256、范围和设备身份检查。网页新计划默认不回读校验，在支持复位的执行器上默认开启“刷完自动复位”。两项都在准备和核对页面的右下角，当前浏览器记住上次选择。修改已预览的选项会重新核对计划，仍需手动确认开始刷写。执行时，页面显示整包和当前分区的进度，分区平均速率按执行器上报的展开载荷字节计算。选项随计划预览确认，写入及所选校验成功才通过原 Fastboot `reboot` 命令复位。复位应答丢失不重试，保留写入已完成与启动未知两个结果；收到复位应答也不等于已观察到操作系统启动。预览、读取、失败和取消都不会触发此复位。

回读阶段默认提供“跳过剩余校验”，也允许用户明确覆盖本次原选“必须回读校验”。复用 `POST /api/flash-selection` 的 `action=skip-verification`，只接受原任务与设备范围内的运行中回读，重复请求幂等。请求者和时间保存在原任务；执行器通过原私有请求文件旁的单向标记，在当前回读块结束后停止剩余校验，不中断 USB 协议、不取消后续分区写入，也不改封存计划。结果记为 `verify_result=skipped`（用户跳过，校验未完成），不能记为 verified；若原先选择刷后复位，全部写入完成且无失败后仍执行一次复位。NOR 写前整片备份与基线、镜像摘要及设备／布局核对不能跳过，已报告的读写或校验错误不能被跳过请求覆盖。未响应或失联仍按原未知结果处理，不自动重放。

摘要明确区分范围：“整分区 SHA-256”覆盖分区全部容量，包括载荷之外的擦除填充；“载荷 SHA-256”对应包内实际写入的文件，两者长度不同时不能直接比较。

已读取 NOR 的工作区在导入镜像、预览替换文件时，复用本次刷前整片备份，按每个载荷的准确字节数，从对应分区起点计算前缀 SHA-256。页面优先显示“与替换文件一致／不同”、比较长度及两侧摘要，整分区摘要另行保留。服务端重新核对封存备份的完整大小和摘要，结果连同备份标识、载荷摘要存入原预览计划；更换文件、备份或设备后不沿用旧结论。不额外读取开发板，不自动取消相同分区的勾选，也不强制整包刷写先备份。系统盘目前只读取布局与版本信息，不能用元数据样本推断完整载荷的摘要。

保留写后 NOR 回读时，同样按已确认计划的实际载荷长度显示前缀摘要对照。关闭写后回读不影响已有刷前备份的对照，但不会生成写后匹配结论。两种对照都不猜测 FIT 长度、不裁剪零或 `0xff`；相等只说明对应的前 N 字节，不代替整分区、整片或分区外保留区域校验。写入前仍沿原机制重新核对板上基线。没有备份或载荷长度时，不编造匹配结论，沿用原摘要及范围标签。

RAM 系统盘适配器对连续相同块复用板上已有暂存缓冲，避免重复 USB 下载；仍执行每块介质写入，保证零区覆盖旧数据。写入进度表示逻辑字节，不表示 USB 实际传输量。读取校验策略取自已确认计划，不使用执行请求中省略或冲突的顶层默认值。

系统盘镜像离线解析预先封存 512／4096 字节扇区对应的载荷及尾部补零摘要。现场整包核对先唯一选择实际扇区对应的候选，再校验范围、容量及写入摘要；不能用尚未绑定现场的默认扇区提前拒绝，也不能仅修改扇区数值而沿用另一种补零摘要。此阶段不再次解包，不改变 GPT 或扩大分区范围。

## 镜像范围与板上内容

镜像以 `fastboot.yaml` 实际引用的分区表确定目标，不能根据文件名或“包里存在某个固件”推断写入范围。
“待刷镜像”显示包内分区、载荷及版本。“目标开发板”下可展开本次读取的已有分区。切换查看的磁盘只切换这份读数。“写入目标与方式”用于选择实际写入的磁盘和范围。未引用的 NOR 材料折叠展示，不自动进入 OS 写入范围；缺少的载荷明确标出。

已读取存储的工作区可以直接导入 OS 包，复用原任务、USB 连接和占用，不必勾选 NOR。
导入生成包内布局和载荷目录。“整包”按包重建分区表并预览全部写入范围，“指定分区”对照现场分区并允许选择部分载荷。确认后才写入。
预览使用已封存的载荷，选择分区不会再次解包。任务轮询不能重置用户选择的刷写方式或覆盖镜像目标视图。

“已下载”统一列出全局及设备内缓存；任务占用镜像时仍显示“正在使用”，禁止再次选择和删除。切换当前来源不覆盖旧缓存。预览与复用计划都读取包内文件系统、版本说明，并与板上内容分开显示。

镜像内容按 SHA-256 保存在 `$SERIALD_BASE/flashing/images/<SHA-256>/`，不按板卡或 USB 连接划分。`image-prepare` 是独立的控制机任务：上传封存或下载完成后自动准备，复用现有任务取消、原请求查询和文件授权，不申请板卡输入／硬件占用。准备使用原有解包、分区表和文件系统解析机制，校验归档及包内 SHA256SUMS，记录载荷和 512／4096 字节填充摘要、基本版本信息，全部成功后原子发布完成记录。重复准备核对文件指纹与配额，不重复解包或扫描大型载荷；修改、缺失或未完成的缓存不能当作已准备结果。

同一镜像可以用于不同板卡；网页主访问身份可明确复用其他板卡上传的镜像，Agent 仍受原文件归属和设备授权限制。镜像准备记录不包含现场检查结果，也不是可执行计划。每次预览都用当前板卡身份和存储布局生成新计划；执行前的实际载荷、设备与范围检查继续保留。任务结束或过期不删除共享镜像内容，NOR 备份和 RAM 工作区仍归原任务保存。

首次准备复用原任务队列，显示归档校验、解压、载荷核对与元数据读取；后续写入预览复用准备结果，只重新核对现场布局和写入范围。解压百分比以实际读取的压缩包字节计数；100% 仅代表压缩输入已读完，随后仍需核对载荷和布局，不能当作刷写完成。计数阶段可按采样速率估算剩余时间，无总量的阶段显示活动指示。预览可以取消；丢失提交响应时按原请求 ID 查询，不重发预览，更不自动刷写。已读取存储的原任务通过独立预览进度展示，不改变“等待选区”的业务阶段。

关闭工作区后，进行中的任务、待确认的计划和需要恢复的任务仍可接续。已查看的成功任务留在任务历史，再点刷机进入准备页。未收到刷写结果时按原请求 ID 查询，结果页显示该次任务记录的写入字节数。任务列表的预览也可重新打开，终态失败仍显示原回执。恢复不扩大板卡／USB 范围，不重提预览或存储写入；过期计划与变化后的现场继续由原服务端校验拒绝。

明确点击“重新检测”或从 USB 列表选择设备时，新一轮操作读取当前连接身份与能力，不再恢复已结束任务的序列号、连接代次或计划。原任务仍在历史中；进行中和需要人工恢复的任务继续优先恢复，不能通过重新检测绕过占用。

预览同时列出全部阶段和整体进度，已完成阶段保留耗时。初次按压缩包大小和保守吞吐量给“初步估算”，后续按同执行器最近 20 个成功预览的阶段耗时中位数、镜像大小与本次实际速率校准。阶段记录复用现有任务元数据，不另建性能数据库，不在启动时跑磁盘／CPU 压测。估算会受压缩率、载荷大小与负载影响；阶段成功以实际回执为准，预估用完也不会提前显示 100%。

gzip 解压复用 goflash 已有 pgzip 的有界预读，重叠解码与文件写入；不依赖额外安装 pigz，也不宣称普通 gzip 可以多核拆分解码。

普通 tar／tar.gz／ZIP 成员及单文件 gzip 解压到新建私有缓存时，全零块通过 seek 与最终 truncate 恢复为空洞，保持逻辑长度与 SHA-256。Windows 先使用原生 `FSCTL_SET_SPARSE`，不支持的卷退回普通写入；Android sparse 导入也启用同一系统标记。展开／缓存配额仍按逻辑长度计数，不因空洞放宽。此优化只减少控制机磁盘分配，不改变包格式、板端写入字节或回读校验。

写入进度按展开后的逻辑载荷计数，剩余时间由本阶段已确认字节估算，不代表 USB 传输量。

执行器错误细分磁盘空间不足、缓存文件缺失、权限和压缩包损坏等原因；网页显示错误码和诊断标识，完整原始原因沿控制机服务日志保存，不将控制机路径放进公共响应。私有执行器计划路径通过现有稀疏 FILL 表达连续重复数据，零块写成零而非 DONT_CARE 跳过，保留原摘要及回读校验要求。

整包刷写默认按镜像包重建 GPT，覆盖目标盘的分区表。内置 K3 加载器按所选设备编号重建，再回读新 GPT 核对范围；空盘也可预览。指定分区继续使用现有分区表。
K3 只有一块系统盘时可自动核对，多盘必须明确选择目标盘。同一 USB 地址和连接代次上确认整包范围后，执行器直接访问预览选定的物理盘，核对盘标识和容量，跳过全盘扫描。写入新 GPT 后读回一次，再按这张表写入各分区。K1 原厂加载器沿用已确认的连接，写入新 GPT 后由 Fastboot 核对目标分区容量。未绑定 USB 地址或连接代次的任务仍执行完整探测。
内置 K3 加载器的指定物理盘路径要求独立核验介质容量，MMC 容量仍仅来自 GPT 时拒绝写入。
同时引用 NOR 和系统盘的混合配方目前拒绝自动缩减范围，需分别生成明确计划。

例如 `Debian-13-GNOME-K3-v1.0rc1-202611150400.tar.gz` 的配置只引用 `partition_universal.json`，目标为 ESP 与 rootfs。
其附带 `partition_nor.json`、EDK2 等文件不表示本次 OS 刷机包含 NOR；选择“整包”也不把这些材料补入目标。

## 从原始镜像内存启动

板卡进入下载模式后，检测 USB 设备，从「已下载」选原始系统包，点击「从镜像内存启动」。控制机按板型和内存预算选择内核、设备树和根文件系统，临时加载器只向内存传输并核对载荷。任务完成表示已交接启动命令，是否进入系统请看串口。复位会退出内存系统并沿原启动链启动。

K1 入口要求 Linux 控制端安装 `spacemit-k1-ramboot-v1` 组件及支持它的执行器。只接纳 EEPROM 型号、序列号和实测 DRAM 布局与 16 GiB MUSE-Pi-Pro 路径相符的设备。原始 Debian 13 Minimal ZIP 可直接使用。同一路径支持已验证的 Bianbu 2.3.5 原始 Minimal ZIP，页面会显示该次内存启动停用 RCPU（远程处理器）及其依赖功能。停用只应用于该镜像的临时设备树。撤下专用组件即可关闭 K1 内存启动入口，正常刷机仍使用原固件随附组件。

## 原版 U-Boot 接入

沿用 SpacemiT U-Boot 的 Fastboot、`UCmd`、`oem read` 和 `upload`。K3 普通刷写、直接 URL 极速刷写和内存启动复用同一临时 U-Boot。新的临时配置继承 FSBL 记录的 USB 速度申请，延续现有 USB 2.0 和 USB 3.0 选择。

`tools/build_ram_loaders.py` 从固定的 U-Boot 提交读取该仓库维护的 `decklab-k3-download.config` 和默认环境。配置保持以下行为。

- 关闭 `BOARD_LATE_INIT`，避开身份配置、DDR 参数持久化和自动刷卡等板级启动动作。
- 仅保留 `ENV_IS_NOWHERE`，避免加载旧持久环境或保存临时环境；关闭可选 EC、retimer 初始化。
- 通过原生 `USE_DEFAULT_ENV_FILE` 加载精简默认环境，`bootcmd` 循环运行 Fastboot、`bootdelay=-2`，避免板级 `.env` 覆盖构建配置。`LOCALVERSION=-seriald-ram` 用于识别匹配的临时构建。
- 保留已有存储驱动和 UUU 命令，启用原生 NVMe、SCSI 命令。
- 启用 `PCI_INIT_R`，PCIe 只在启动时枚举一次，否则每条 `nvme` 命令都要重新枚举（约 1.1 秒）。
- 刷写前检查加载器是否支持原生 `unzip`。支持时，仅在传输加解压的估算耗时更短时发送 gzip。其他数据原样发送，各段使用同步写盘。
- 已核对的 K1/K3 USB 下载入口由 FSBL 解析 FIT，按配置装载供应商 OpenSBI、U-Boot 及其设备树。随后 Linux 内核、系统设备树和 initramfs 由 U-Boot 分别接收并经 `booti` 启动。

K3 FSBL 由 `tools/build_k3_fsbl.py` 从供应商 U-Boot SPL 源码原样构建（不改源码），并记录两块训练固件在镜像中的偏移。USB 下载模式下它不读板上保存的训练结果：第一次加载完整训练，执行器从 SRAM 取回结果（`ddr-training` 事件），后端按板子序列号存入刷机工作目录的 `ddr-training.json`；之后同一 USB 口的加载把结果写入 FSBL 镜像，省去约 5.6 秒，临时环境须报出同一块板的序列号（否则 `loader-training-mismatch`）。临时环境未启动（`loader-fsbl-timeout`）、内存自检失败（`device-ram-unstable`）或板子不符时作废该结果，下次重新训练。不写板子。

BootROM 下载模式下可在预览前选择 DeckLab 内置或镜像自带的临时 FSBL / U-Boot。两份材料作为一组按摘要绑定到预览，只装入 RAM。仍按镜像中的分区配置和预览范围写入。设备已经运行加载器时，须重新进入 BootROM 才能更换。

`spacemit-ram-v1` 是主机端材料兼容版本。内置 K3 使用上述配置，提供额外的存储核对、备份和回读能力。K1 内置材料来自 Debian Firmware 包，使用原版刷机路径。可用 `tools/package_flash_loaders.py SOURCE DEST --k1-firmware ARCHIVE --k1-sha256 SHA256` 合并到打包材料，脚本校验归档及包内构建回执。

原版路径支持与芯片匹配的 NOR 整包预览，K1 为五个分区，K3 为六个分区。K1 OS 整包使用原版 Fastboot 选定的活动系统盘，预览明确列出覆盖 GPT。确认后按 `partition_universal.json` 写入 GPT，再核对新分区，全部通过才发送载荷。K1 从 NOR 启动时，原版加载器的分区容量查询只查 MTD。控制机通过同一加载器只读取得系统盘 GPT，检查 CRC、分区起点、长度及 MTD 同名冲突。设备检测也复用此路径，在「板上已有内容与备份」中显示当前 GPT。加载器只用 `blk-size=universal` 确认介质可用，剩余空间在新 GPT 建立后分配。空盘和旧 GPT 损坏都可走此流程；指定分区仍必须核对已有 GPT。已进入可用 U-Boot 时可直接预览，无需重新加载。整包刷写先选 OS，然后可在「配套 Firmware」单独选本地文件或镜像库中的包，也可替换自动匹配的固件。读取设备存储后仍可在原任务选配套固件，组合预览会核对固件对应的 NOR 布局。选「仅刷当前镜像」可清除配套固件。Firmware＋OS 共用一组临时加载器，两部分范围均确认后依次执行。写入预览按存储介质绘制分区、写入和擦除范围。

| 操作 | 使用的原生能力 | 主机负责的检查 |
|---|---|---|
| NOR 容量与布局 | `mtd list`、`env set mtdids/mtdparts`、`mtdparts` | 单一 NOR、容量、擦除块、实际分区偏移与容量；临时映射不写存储 |
| NOR 备份 | `oem read:mtd`、`upload` | 完整传输长度、分块进度、整片摘要 |
| NOR 分区写入 | 下载载荷后执行 `UCmd:mtd erase … && mtd write …` | 只允许明确选定的分区、擦除对齐与容量；写前备份、写后整片回读 |
| 系统盘枚举与读取 | NVMe／SCSI／MMC／USB 原生命令、`oem read:mem`、`upload` | 指定设备、偏移和长度，读取预算与分区边界 |
| 系统盘分区更新 | 下载分块后执行指定 NVMe／SCSI 等原生 `write`，再按原生 `read` 回读 | 写前再次核对物理盘、容量与 GPT；分块边界限制在选定分区；未知写入不重试，回读摘要必须匹配 |
| EEPROM 身份与配置 | 控制 DTB、`i2c read`、`tlv_eeprom read`、`config:write` / `config:flush` | 解析物理 TLV、CRC、唯一字段、旧值；一次写入后比较完整有效内容 |

控制台回传和下载载荷共用 Fastboot 缓冲区。普通读命令使用独立暂存地址；载荷下载至执行写入命令之间不读取控制台。命令由执行器根据固定模板和已校验参数生成，API 不接受 U-Boot 脚本、内存地址或任意命令。

原生 `oem read` 的偏移本来就是 64 位。MMC 命令的块号仍受原实现限制，主机拒绝超出其范围的读取。NVMe／SCSI 的容量来自设备实际块数与块大小；此版本 MMC 未输出精确容量，使用有效 GPT 几何并明确标记容量未独立验证，不把 GPT 当成物理容量证明。

## 读取设备存储

无需业务镜像，点击“读取设备存储”在同一任务中完成：

1. 加载匹配的 RAM 环境，读取并发布 NOR 整片备份，可下载并查看 SHA-256。
2. 显示 NOR 六个标准分区的版本、构建时间、容量与摘要。版本只取实际 FIT 字段或组件横幅，不由文件名推测；env 内容不在页面公开。
3. 读取系统盘 GPT 与少量 FAT／ext 元数据，显示 os-release、模块和启动配置中的版本。每盘布局最多 1 MiB，总元数据预算 32 MiB，单分区预算 8 MiB；不复制整个系统盘，不挂载文件系统。未知或超预算明确显示未知。

准备页分别展示镜像内的 NOR / OS 布局和板上实际读取的 NOR / 系统盘布局。包内文件按分区、载荷大小、软件版本列出，附带分区表可展开查看。核对页按目标介质展示预计写入、擦除和可确定的保留分区。重写 GPT 时使用计划中的范围。系统盘视图不改变 NOR 写入选区。多盘时不将第一块盘当作默认盘。
根据[第二启动介质指南](https://www.spacemit.com/community/document/info?lang=zh&nodepath=software/SDK/bianbu/development/second_boot_device_guide.md)，EEPROM TLV `0x83` 优先于 DTS，默认优先级为 UFS → SSD → eMMC → USB。临时环境中的 DTS 不代表板上 NOR 固件的 DTS；只有可确认的 EEPROM 配置与唯一匹配设备才标记默认介质，否则保留实际列表供选择。
UFS 在原生存储列表中使用 `scsi:N`（界面为 UFS / SCSI）。修改优先启动介质并回读确认后，复用本任务已读取的设备列表重新关联唯一匹配系统盘；旧任务缺失该关联时，页面也可据此选择信息视图。有多个匹配盘或缺少对应介质时仍需人工选择，查看系统盘不改变刷写选区，配置关联不代表操作系统已启动。

网页重新打开任务或从历史记录恢复时，通过现有能力查询恢复“刷后自动复位”等执行器能力；查询不探测 USB、不更换原任务连接代次、不重置镜像及选区。等待选区时允许修改并重新预览，写入开始后禁用这些选项。
包目录缺失或解析失败时，预览入口允许用户显式重新解析，并在成功后继续生成所选范围预览；此过程只提交预览请求，不自动确认刷写。正在解析时禁止重复点击，切换设备或任务后不采用旧响应。
NOR 包不携带系统盘目标。切换回读校验重新解析时保留已经识别的介质类型，避免误带系统盘默认值；系统盘包的指定设备只允许原有配置编号或 `nvme|scsi|mmc|usb:0..3` 原生编号，保持现场身份与范围复核。

## EEPROM

先从运行中的控制 DTB 确认已启用的 24C02 EEPROM 及 I2C 总线，再用原生 I2C 命令读取物理 256 字节。主机校验 TLV 头、长度、CRC、重复字段和序列号字符。TLV `0x23` 用于关联原板卡记录，保留标签与历史；`eeprom-serial` 是执行器结果中的物理读取依据，不向固件查询同名 getvar。不生成或改写序列号。无有效编号时保留 USB 临时身份；BootROM 需先进入 RAM 环境才能读取。

“保存到 EEPROM”只修改 TLV `0x83`，允许 SSD、UFS、MMC、USB。主机先核对当前身份和旧值，检查修改后的完整 TLV 是否放得进 EEPROM，刷新原生暂存区后发送 `config:write SecondBootDev@eeprom:值`，再发送一次 `config:flush`。原版命令的 OKAY 不代表物理写入已验证；随后重新读取 EEPROM，比较完整有效 TLV，确认序列号、MAC 和其他字段均保留。失败或断线保持未知，不重试、不自动重启。配置在下次启动生效。

配置操作复用 `POST /api/flash-selection`，使用 `action=boot-priority`、原任务与连接代次、`request_id`、`expected`、`value`。只允许当前等待选区的人工任务；请求号与输入、结果持久保存，同号查询不重复写入。身份关联只补充原任务可见性和板卡锁，不更换任务或文件授权范围。

## 写入范围与回读

指定分区默认不选任何项。完整包按包内映射提供候选载荷，也可在某一行选择独立文件；只有一个已选分区时，顶层单文件才自动绑定该行。允许全选，缺失载荷时拒绝预览。修改文件或选区立即使原预览失效。

写入方式（普通刷写与极速刷写相同）：数据段首段 16 MiB、之后逐段翻倍，最多 128 MiB，并受设备上报的 `max-download-size` 限制。整 1 MiB 的全零段不经 USB 传输：DeckLab 临时 U-Boot 写系统盘时，由设备内存中预先清零的区域直接写盘；经 Fastboot `flash` 写入时，编码为 sparse FILL 块。旧数据都会被覆盖，写入摘要和回读结论不变。K3 临时 U-Boot 写入的数据段在主机切成独立 zstd 帧，板上多核解压、核对长度后写盘，写盘与下一段下载重叠；旧加载器自动退回 gzip 与同步写盘。每段按实测 USB 与解压速率决定压缩还是原样发送。普通刷写边写边计算载荷摘要，与预览时的摘要不符即失败；稀疏文件的空洞不读盘。耗时公式与各参数实测值见 [刷写耗时模型](FLASH_PERFORMANCE.md)。

确认前展示实际偏移、写入字节、补零、分区容量和擦除范围。`write_layout=false` 不添加分区表、其他介质或 EC 写入。原版 `flash:env` 有导入和保存环境的附加行为，NOR 分区路径使用原生 MTD 命令避免这些副作用。

写入前重新读取整片 NOR，核对备份文件和板上基线是否变化。每个分区的载荷及补零摘要必须匹配计划；擦除块不得越出所选分区。任何失败立即停止，未知结果不重放。写后整片回读，比较实际写入范围及全部所选分区以外的字节。所选分区内未被载荷覆盖的擦除尾部不编造预期值，但保存在回读文件中。

整包入口不需要逐项勾选，按完整包固定映射预览全部范围后确认；包含 env 时会替换其内容。匹配的 K3 RAM 环境复用上述原生 MTD 与回读流程。管理员配置的其他加载器按自身能力预览；旧式完整恢复的 `flash:mtd` 会擦除 env，不能用于指定分区。

备份和回读使用现有 TransferArtifacts 的鉴权、配额及保存期限。网页读取板上布局时创建任务内临时 NOR 快照，供版本解析与选区比较复用。核对写入范围时可选择保留写前备份。支持整片 NOR 读取且已核对布局的整包计划，也可在此时选择写前备份，默认直接刷写。已发布的同一文件在保存期内可多次下载，默认保存期为最后访问后七天。新的读板任务重新采样。未选择保留的网页写前快照在任务成功或写入前取消、失败后由清理器回收；写入结果不确定或需要恢复时保留现场。旧任务和未请求临时快照的接口调用沿用原保存期。关闭面板或刷新不重启任务。进度来自实际字节，分别显示准备、读取、写入和回读；错误提示不被等待截止时间覆盖。等待选区最多十分钟。

## 极速刷写系统盘

K3 从 BootROM 进入极速刷写时，复用普通刷写和内存启动使用的内置 FSBL 与 U-Boot。

K3 下载设备的刷机面板中有「极速刷写系统盘」，填系统包 URL（`.tar.gz` / `.tgz` / `.tar`）即可开始。执行器边下载、边用多线程解压、边解析 tar，数据只在内存中流转，直接写入系统盘，不经过「下载 → 准备镜像 → 预览」三步，控制机也不落盘。内存占用上限默认 1 GiB。

- 包内必须先出现 `partition_universal.json`。执行器按它重建 GPT 并回读核对，之后才写任何载荷；Debian 系统包满足这个顺序。如果较大的载荷排在分区表之前，会在写入前拒绝，请改用普通刷写。
- 设备在 BootROM 时，自动装入内置的临时 FSBL / U-Boot。设备已在 DeckLab 临时 U-Boot 时直接继续。目标盘可选 `auto`（板上只有一块盘时）或 `nvme:0`、`scsi:0` 这类编号。
- 写入方式与普通刷写相同（见上节）：整 1 MiB 的全零块不经 USB 传输，由设备内存中的零区直接写盘，旧数据仍被覆盖；数据段压缩传输、板上解压。
- 结束时按包内 `SHA256SUMS`（或 `md5sums.txt`）核对每个已写载荷。由于是边下边写，核对不通过时数据已经写入，任务会失败并要求重刷。中途断网或取消，系统盘可能只写了一部分，任务记为 `partial-or-unknown`。
- 只写系统盘，不写 NOR 固件。仅限网页操作者使用，Agent 令牌无权调用。

## 刷写配置

K3 下载设备的刷机面板中有「刷写配置」。点「实测并生成配置」：

1. 在板上测量 USB 下载、板上解压、写盘和命令开销；写盘测速读出 128 MiB 后原样写回，内容不变。
2. 在控制机测量各压缩级别的速度和压缩比。
3. 按[刷写耗时模型](FLASH_PERFORMANCE.md#实测生成刷写配置)选出编码、压缩级别、段大小和是否后台写盘，保存为这个 USB 口的配置。

之后经该 USB 口的普通刷写和极速刷写都使用这套配置；没有自己配置的 USB 口，沿用同型号最近一次实测。面板显示配置来源和各项实测值，可以清除。配置只影响速度，不改变写入内容。仅限网页操作者使用。

## MCP 入口

这些能力也通过 [MCP 工具](MCP.md#usb存储与刷机)提供。工具直接适配现有 HTTP API、
任务和文件服务，不修改 goflash 或 U-Boot。`read_device_storage` 创建读取工作区，
`get_task` 返回备份、分区版本和系统盘信息；`get_artifact` 提供带原授权访问的下载地址。
整包／分区用 `preview_flash` → `start_flash`；等待选区时用
`preview_flash_selection` → `confirm_flash_selection`。读取工作区内可先传 `artifact_id` 与空 `selections` 获取包目标和系统盘布局，再传所选候选与 `source_plan_id` 复用载荷；布局参数仍使用原任务的 `layout_digest`。EEPROM 修改用 `set_boot_priority`。
整包预览遇到 BootROM 时，网页会在准备阶段加载临时环境并核对现场布局。现场计划就绪后，用户确认一次才写入。未知写入不重放，备份和镜像归属于原任务调用者。

## 验证边界

软件回归使用模拟设备，不接触真实串口或存储。RAM 材料必须实际编译并检查配置；Windows 需要原生运行软件回归，交叉编译不能代替硬件验收。

K3 的受限实板验证覆盖原版源码与原生 Kconfig 构建的 RAM U-Boot、物理 EEPROM
身份、整片 NOR 备份、系统盘容量和文件系统元数据读取，以及原内容的单分区回写和
写后完整回读。该结果不自动扩大为其他板型、不同版本、多分区或完整恢复的硬件验收。
具体设备标识、接线、原始日志和完整备份属于本地运行数据，不随源码或公开安装包发布。

Windows 的隔离原生验证覆盖安装包、串口/USB 适配与图形客户端的软件行为；
模拟控制器回归不等同于真实硬件写入。K1 原版加载器与五分区恢复已覆盖离线预览和模拟容量核对，真实板卡写入、NOR 单分区和无镜像读取尚待验收。

镜像准备完成后按 NOR、系统盘显示分区和载荷范围。大小为 `-` 的分区扩展到实际磁盘末尾。整包模式下可将同介质的附带分区表应用到对应的刷机配置，生成独立的控制机目录版本并重新预览；目标介质的载荷来自执行该配置的镜像。整包刷写时，可在「配套 Firmware」选择当前 OS 包中的 SPI NOR 分区表。两个介质共用已准备的镜像目录，NOR 按所选表写入，系统盘按 GPT 写入。SD 卡制作用的 `partition_flash.json` 不参与 USB 刷写选择。
