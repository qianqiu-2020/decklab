# 发布验收

先确定候选标签、提交号及目标平台。所有附件均来自该提交，发布后可以用同一份校验文件复核下载内容。

| 对象 | 检查与证据 |
| --- | --- |
| 源码 | 同一提交在主分支的 Python、浏览器、Windows 和跨节点回归通过 |
| Linux | 在 Ubuntu 22.04 和 24.04 验证全新安装、旧包升级与数据保留，断网后使用 API 和 MCP |
| Windows | 实际运行安装器，验证快捷方式、USB 驱动识别、旧目录升级、文件清单、卸载后数据保留 |
| 交付内容 | 检查版本化文件、固定下载别名、SHA-256、已安装文件回执及第三方声明 |
| 本地计时 | 同一次记录列出平台、两种构建模式的开始及结束时间、缓存范围和实际输出 |

独立验收不连接测试板。若本次改动涉及刷写介质、串口采集、USB 枚举或启动模式，发布说明应明确列出已验证的实板路径。通过[开发流程](../../CONTRIBUTING.md)说明如何运行模拟设备和回归。

草稿发布前后使用 `tools/verify_release.py` 核对实际下载包。需要调查旧版本的实际出包记录时，可参考[历史验收记录](https://github.com/qianqiu-2020/decklab/blob/f0ffcbc/docs/RELEASE_ACCEPTANCE.md)。
