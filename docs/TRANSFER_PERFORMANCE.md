# 串口传输速率核对

2026-09-21，以 `deb1:/root/log.txt → milkv2:/tmp/log.txt` 的 311,077 字节文件覆盖复制为基线。
1.4.24 使用 2 KiB 分块时，`serialctl file-copy` 记录：整体 39.778 秒（7.64 KiB/s），
源读取请求累计 21.762 秒（13.96 KiB/s），目标写入请求累计 39.178 秒（7.75 KiB/s）。
两段请求已经重叠；整体几乎等于目标写入，因此瓶颈在目标上传路径。此前 `deb1` 单独下载的
13.19 KiB/s 不能代表 `milkv2` 的写入速率。

同一文件的 152 个 2 KiB 分块均达到 gzip 阈值；上传方向的 Base64 数据合计约 123,552 字节。
115200 波特、8N1 下，仅发送这些字节的理论下限约 10.7 秒。目标请求累计 39.2 秒，差额约
28.5 秒包含每块 shell 命令、解码、追加、确认和 HTTP 往返，不能单独归因于某个进程。

1.4.25 将分块上限提至 8 KiB。可压缩数据通常用大块减少往返；若完整命令超过典型
4095 字节终端行长，服务返回 413，客户端在同一偏移自动拆半重试。每块响应帧、连接代次
检查和最终 SHA-256 校验保持不变。升级后用同一路径、同一文件重新测试，比较
`rate_diagnostics` 的 `source_kib_s`、`destination_kib_s`、`effective_kib_s`。这些数值按
客户端请求耗时折算，并非串口波特率。若目标写入仍慢，应进一步计时板端解码与回显/确认阶段。

1.4.25 实板复测：同一 311,077 字节文件整体 21.991 秒（13.81 KiB/s），源读取请求累计
10.888 秒（27.90 KiB/s），目标写入请求累计 20.714 秒（14.67 KiB/s）；目标方向依旧限制整体。
本样本按 8 KiB、gzip 级别 1 编码共约 91,428 字节 Base64，理论串口发送至少 7.94 秒，
38 次目标请求另耗约 12.8 秒。

1.4.26 调整为 10 KiB 和 gzip 级别 6，同一路径连续两次实板复测分别为 19.501 秒
（15.58 KiB/s）和 19.532 秒（15.55 KiB/s），SHA-256 均为
`678ea68e4ada43b39fd0f010ca957e2b4732f21142d1cc7fae3e9b0b06f1315c`。
目标请求均约 18.0 秒，源请求均约 10.2 秒。此样本的 31 个上传块共约 80,964 字节
Base64，纯串口发送下限约 7.03 秒；余下约 11 秒含板端 shell、gzip、回显和请求确认。
这是当前逐块确认协议下实测最快的配置，不等于串口链路的理论上限。继续明显提速需要
批量或流式上传协议；实施时须保留连接绑定、传输失败时的临时文件隔离和最终 SHA-256 校验。

1.4.27 加入批量上传：最多三个 10 KiB 原始块合并为一次 HTTP 请求和一次串口响应帧，
各块仍分成不超过 4095 字节的终端输入行。目标在整批写完后报告文件长度；请求失败则
标记结果不确定并废弃临时文件，不会覆盖目标。板间复制继续在目标写入时预读下一批源数据。
需要用相同文件实测，确认多行粘贴在真实板子的串口输入队列里不丢字，并比较速率。

1.4.27 首次实板请求中，目标板首批返回 `SD_RC=0`、`SD_SIZE=30720`，但服务误判失败。
原因是批量命令后续行的终端回显落在响应帧内，早于真实结果且含同名字段；临时文件
按失败路径清除，原目标文件未替换。1.4.28 改为取响应帧里最后一条完整结果字段，
并补回归测试；批量实际速率仍需复测。

1.4.28 的第二次实板测试定位到另一个解析细节：Bash bracketed-paste 退出序列后，
真实结果前会出现单独的 `\r`，例如 `\rSD_RC=0\r\nSD_SIZE=30720`。1.4.29 在提取
状态字段前把回车规范化为换行。两次失败均在首批正确写入后由服务清理临时文件。

1.4.29 同一路径实板连续两次成功：15.560 秒（19.52 KiB/s）和 15.853 秒
（19.16 KiB/s），目标请求累计 13.374 / 13.688 秒，源请求累计约 10.3 秒；
两次目标 SHA-256 均与源文件一致。相对 1.4.26 约 19.5 秒，批量约节省 3.8 秒。
三块一批的最坏情况未压缩请求约 41 KiB Base64，低于 64 KiB HTTP 上限，
115200 8N1 的纯发送时间约 3.6 秒，也给写入 5 秒超时留出余量。
